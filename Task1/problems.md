### Список проблем:
- Все конфиденциальные данные хранятся на 1 сервере - риск потери всех данных в случае неисправности диска.
- Конфидецнаильные данные (персональные данные и медицинские данные) не шифруются.
- Неограниченный доступ ко всем персональным и медицинским данным со стороны мед работников - доступ к файлам данных всех пациентов и результатам анализов всех пациентов.
- Отсутствует логирование действий - просмотр, копирование, модификация файлов. Это может сделать невозможным проведение аудита безопасности системы и расследование инцидентов.
- Внутренние потоки данных никак не контролируются, что формирует риск утечки конфиденциальных данных
- Негарантированная согласованность между различными сервисами - мед работник/администратор может опечаться в ФИО во время ручной обработки и по итогу результаты анализов могут прийти не на того пациента.

### Список данных для защиты:
- Персональные данные (ФИО, пол, возраст, телефон, адрес, ...)
- Медицинские данные (жалобы, диагноз, рез-ты анализов, ...)
- Финансовые даныне (чеки, бухгалтерские данные, ...)

### Меры защиты:
- Персональные данные:
    - При хранении - шифрование файлов AES.
    - При передачи - использование защищенных каналов с исползованием TLS, SSL версии > 1.2.
    - RBAC и ABAC контроль доступа.
    - Раздельное хранение сканов персональных данных и медицинских данных
- Медицинские данные:
    - При хранении - шифрование файлов AES.
    - При передачи - использование защищенных каналов с исползованием TLS, SSL версии > 1.2.
    - RBAC и ABAC контроль доступа.
    - Раздельное хранение сканов персональных данных и медицинских данных
- Финансовые данные:
    - При хранении - шифрование файлов AES.
    - При передачи - использование защищенных каналов с исползованием TLS, SSL версии > 1.2.
    - RBAC и ABAC контроль доступа.
    - Обфускация данных - токенизация (замена персональных данных в платежах на единый уникальный идентификатор)

### Тегрирование:
По типу данных:
- Персональные данные: `pers_data`
- Мидицинские данные: `med_data`
- Финансовые данные: `fin_data`
- Другие: `other_data`
По источнику данных:
- Лабораторные данные анализов: `lab_results`
- Докторские данные - то что заполняют доктора: `doctor`
- Данные пациента (patient data - из excel файла): `patient`
- Данные о платежах (чеки): `fin`
- ТМЦ: `tmc`
